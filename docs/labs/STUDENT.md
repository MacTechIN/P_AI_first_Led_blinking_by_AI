# 실습 매뉴얼 — 각자의 PC에서 직접 해 보기

**30분, 각자의 PC 한 대.** 카메라도 아두이노도 GPU도, **인터넷도 필요 없습니다.**

터미널을 처음 써도 됩니다. 아래 순서대로 치고, **화면에 나온 것과 비교**하면
됩니다.

---

## 0. 왜 시뮬레이터인가 (1분만 읽으세요)

실물 장비는 교실에 한 벌입니다. 카메라도 하나, LED 보드도 하나, AI 모델을
돌리는 GPU도 하나입니다. **스무 명이 동시에 만질 수 없습니다.**

그래서 그 한 벌을 각자의 PC 안에 옮겨 놓았습니다.

```
   색지를 보는 카메라  →  색을 알아내는 코드  →  판단  →  LED 를 켠다
        (가상)              (실물과 같은 것)            (가상)
```

가운데 **"색을 알아내는 코드"와 "판단"은 실물에서 돌던 그대로**입니다.
양 끝의 카메라와 LED만 가상입니다. 그래서 여기서 통하는 것은 실물에서도
통하고, 여기서 막히는 것은 실물에서도 막힙니다.

**중요한 점 하나** — 이 시뮬레이터는 잘 되는 모습을 보여주려고 만든 것이
아닙니다. 실제로 겪은 고장 여덟 가지를 그대로 재현합니다. LED 색이 명령과
달라 보이면 **그게 맞습니다.** 저항 하나를 세 색이 나눠 쓰는 실물의 성질을
흉내내고 있습니다.

---

## 1. 복사하기 (2분)

1. USB 의 **`pai-sim` 폴더 전체**를 각자의 PC에 복사합니다. 바탕화면도 좋습니다.
   - 폴더 일부만 복사하면 안 됩니다. `wheels` 폴더가 빠지면 다음 단계에서 막힙니다.
2. 복사한 폴더를 **터미널에서 엽니다.**

| 운영체제 | 여는 법 |
|---|---|
| **윈도우** | 폴더 안에서 `START.bat` 을 **두 번 누릅니다**. 끝입니다. |
| 윈도우 (직접) | 주소창에 `cmd` 를 치고 Enter |
| macOS | 폴더에서 마우스 오른쪽 → "폴더에서 새로운 터미널 열기" |
| Linux | 폴더에서 마우스 오른쪽 → "터미널에서 열기" |

## 2. 처음 한 번 (3분)

```
python START.py
```

> macOS·Linux 에서는 `python3 START.py` 입니다. 윈도우에서 `python` 이 안 되면
> `py START.py` 를 해 보세요.

처음 한 번은 `numpy` 를 **USB 안의 파일로** 설치합니다. 인터넷을 쓰지 않습니다.
이런 화면이 나오면 성공입니다.

```
P-AI 시뮬레이터 — 장비 없이 제어 루프를 돌립니다
==============================================
· 루프 동작: red #ff0000 49% 중앙 (채도 211, 밝기 124)
· 장면 대본 3개: basics, dusk, sweep
· OpenCV: 있음 (빠름)

준비됐습니다. 아래 순서대로 해 보세요.

  python3 START.py 1      루프가 닫혀 있다 (5분)
  python3 START.py 2      환경이 변하면 무너진다 (5분)
  python3 START.py 3      대본이 곧 골든셋 (5분)
  python3 START.py 4 <팀번호>   결함 진단 (10분)
```

`OpenCV: 없음 — numpy 로 대체합니다` 라고 나와도 **괜찮습니다.** 조금 느릴 뿐
결과는 같습니다.

막히면 맨 아래 **"잘 안 될 때"** 를 보세요.

## 3. 1단계 — 루프가 닫혀 있다 (5분)

```
python START.py 1
```

화면 왼쪽에 **색지**, 오른쪽에 **작은 불빛**이 보입니다. 색지가 빨강 → 초록 →
파랑으로 바뀌고, 불빛이 따라옵니다.

> 색이 안 나오고 글자만 나와도 됩니다. 터미널이 색을 지원하지 않는 것뿐입니다.

글자는 이렇게 나옵니다.

```
*[0000] red #ff0000 49% 중앙 (채도 211, 밝기 124)  →  blink 150ms #ff0000 @212   (123ms = 촬영 119 + 특징 3 + 판단 0 + 구동 0)
 [0001] red #ff0000 49% 중앙 (채도 211, 밝기 124)  →  blink 150ms #ff0000 @212   (117ms = 촬영 114 + 특징 3 + 판단 0 + 구동 0)
```

읽는 법:

| 부분 | 뜻 |
|---|---|
| `[0000]` | 몇 번째 프레임인가 |
| `red ... 49% 중앙` | **본 것** — 빨간색이 화면 가운데 49% 를 차지한다 |
| `→ blink 150ms` | **한 일** — LED 를 150ms 주기로 점멸시켜라 |
| `(123ms = 촬영 119 + ...)` | 한 바퀴에 걸린 시간과 그 내역 |
| 맨 앞의 `*` | **이 프레임에서 명령을 실제로 보냈다** |

### 여기서 확인할 것 두 가지

**① `*` 가 색지가 바뀐 프레임에만 붙습니다.**
같은 판단이면 보내지 않습니다. 끝에 나오는 줄을 보세요.

```
명령 전송 3회 / 288 스텝  — 시리얼이었다면 10줄
```

**288번 봤는데 3번만 보냈습니다.** 색지가 세 장이었으니까요.

**② 빨강만 점멸합니다.** 규칙이 그렇게 정해져 있습니다. 경고에 가까운 색일수록
빠르게 반응하도록요.

## 4. 2단계 — 환경이 변하면 무너진다 (5분)

```
python START.py 2
```

이번에는 **색지가 바뀌지 않습니다. 조명만 꺼집니다.** 끝까지 보세요.

```
*[0000] green #00ff33 49% 중앙 (채도 201, 밝기 110)  →  on #00ff33 @212

```

어느 순간 **`물체 없음`** 으로 바뀝니다.

### 한 줄로 답해 보세요

> **색이 사라진 건가요, 색을 믿지 못하게 된 건가요?**

<details>
<summary>생각해 본 뒤에 펼치세요</summary>

둘째가 맞습니다. 색지는 그대로 초록입니다. 다만 어두우면 색조는 노이즈가 되기
때문에, 코드가 **일부러 포기**합니다.

오늘 강의에서 본 모델은 거의 깜깜한 화면에서도 끝까지 "초록" 이라고 답했습니다.
능력의 문제가 아니라 **기권할 줄 아느냐**의 문제입니다.

## 5. 3단계 — 대본이 곧 골든셋 (5분)

```
python START.py 3
```

장면 파일에는 **언제 무엇이 일어나는지**만 적혀 있는 게 아니라, **그때 무엇이
맞는지**도 함께 적혀 있습니다. 그래서 장면이 그대로 시험이 됩니다.

```
basics · 24초 · 사건 3 · 기대 3 (+기록 3)
  PASS    4.0초  빨강은 경고라 점멸한다
  PASS   12.0초  일치
  PASS   20.0초  일치
...
9/9 통과
```

### 이제 일부러 고장을 넣어 봅니다

```
python host/scenario_check.py --quiet --fault stale-roi
python host/scenario_check.py --quiet --fault no-hysteresis
```

| 넣은 고장 | 결과 |
|---|---|
| `stale-roi` (엉뚱한 곳을 본다) | **1/9** — 잡아냅니다 |
| `no-hysteresis` (명령을 쏟아낸다) | **9/9** — 못 잡습니다 |

**둘째 줄이 이 단계의 핵심입니다.** `no-hysteresis` 는 진짜 고장입니다. 정지
화면에서도 명령을 열 배 넘게 보냅니다. 그런데 **화면에 보이는 건 그대로**라
전부 통과합니다.

기대값에 "무엇이 보이는가" 만 적고 **"얼마나 자주 보내는가" 는 적지 않았기
때문**입니다.

> **적어두지 않은 것은 지켜지지 않습니다.**

직접 세어 보세요.

```
python host/sim_demo.py --still --steps 20 --no-preview
python host/sim_demo.py --still --steps 20 --no-preview --fault no-hysteresis
```

정지 화면 20장에서 명령이 **1회 → 9회**로 늘어납니다.

## 6. 4단계 — 결함 진단 (10분)

강사가 팀마다 **다른 번호**를 줍니다. 아래 `17` 을 받은 번호로 바꾸세요.

```
python START.py 4 17
```

```
── 4단계 · 결함 진단 ──
이 장비에는 문제가 하나 있습니다. 증상만 보고 원인을 찾으세요.

이 장비에는 문제가 하나 있다고 신고됐습니다.
  증상: LED 가 색지를 몇 초씩 늦게 따라간다
  어느 계층인지, 무엇 때문인지 측정으로 밝히십시오.
```

**무엇이 들어갔는지는 알려주지 않습니다.** 증상에서 시작합니다.

### 규칙

- **`--reveal` 은 답을 말한 뒤에 씁니다.** 먼저 보면 실습이 끝납니다.
- `sim/faults.py` 를 여는 것도 똑같습니다. 답지입니다.

### 계층을 순서대로 잘라 나갑니다

| 계층 | 던질 질문 | 재는 법 |
|---|---|---|
| 센서 | 프레임에 정보가 있나 | 표준편차를 본다 |
| 특징 | 보는 자리가 맞나 | 같은 프레임을 올바른 범위로 다시 본다 |
| 판단 | 정지 장면에서 조용한가 | `--still` 로 전송 횟수를 센다 |
| 구동 | 명령한 색 = 켜진 색인가 | 둘을 나란히 적는다 |
| 모델 | 전부 실패인가 일부인가 | 요청 수와 실패 수를 비교한다 |

**마지막 줄만 외워도 됩니다 — 전부 실패하면 전송 문제, 일부만 실패하면 계약
문제입니다.**

### 가설을 직접 켜 보는 법

의심되는 고장을 직접 넣어 보고, 증상이 같은지 봅니다.

```
python host/sim_demo.py --fault list
python host/sim_demo.py --fault stale-roi --steps 20 --no-preview
```

더 자세히 보려면:

```
python
```
```python
from sim import build_rig
rig = build_rig("stale-roi")          # 의심하는 고장 이름
with rig.source as src:
    obs = src.read()
    print(obs.image.std())            # 센서 — 0 에 가까우면 센서 문제
    print(rig.extractor(obs.image))   # 특징 — 무엇을 봤는가
    print(rig.world.emitted())        # 구동 — 실제로 켜진 색
```

(`exit()` 로 빠져나옵니다.)

### 답을 적습니다 (네 줄)

| | |
|---|---|
| 증상 | 내가 **본** 것 |
| 지목한 계층 | |
| 근거 | 다른 계층을 **배제한 측정** |
| 재발 방지 | 같은 고장을 **자동으로** 잡으려면 |

**"센서인 것 같다" 는 답이 아닙니다.** "표준편차가 0 이 아니므로 센서는
아니다" 가 답입니다.

마지막 줄이 빈 보고서는 반쪽입니다. 원인을 찾는 것보다 **다음에 자동으로
잡히게 만드는 것**이 일의 끝입니다.


## 잘 안 될 때

**`python` 을 알 수 없는 명령이라고 할 때**
윈도우면 `py START.py`, macOS·Linux면 `python3 START.py` 로 해 보세요.
그래도 안 되면 각자의 PC에 파이썬이 없는 것입니다. **강사에게 말씀하세요.**

**numpy 설치가 실패할 때**
화면에 찍힌 **파이썬 버전과 운영체제**를 강사에게 보여 주세요. USB 안에 그
조합에 맞는 파일이 없는 경우입니다.

**`wheels 폴더가 없습니다` 라고 할 때**
USB 에서 폴더 **전체**를 복사하지 않은 것입니다. 다시 복사하세요.

**`[38;2;...m` 같은 글자가 쏟아질 때**
터미널이 색을 지원하지 않습니다. `--no-preview` 를 붙이면 글자만 나옵니다.

```
python host/sim_demo.py --scenario basics --no-preview
```

**그림이 깨져 보일 때**
창을 넓히거나 글꼴 크기를 줄이세요.

**명령을 멈추고 싶을 때**
`Ctrl` + `C` 를 누릅니다.

## 오늘 가져갈 네 가지

> **① 루프는 닫혀 있다** — 명령한 것이 다음 프레임에 보입니다.
> **② 환경이 변하면 판단이 무너진다** — 그리고 포기할 줄 아는 것이 능력입니다.
> **③ 성공 신호는 작동의 증거가 아니다** — 장치가 보여도, `ok` 라고 해도.
> **④ 적어두지 않은 것은 지켜지지 않는다** — 9/9 를 통과한 고장이 있었습니다.

더 깊이 보려면 `docs/08-fault-clinic.md` 를 읽으세요.
