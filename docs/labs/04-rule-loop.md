## 목표

AI 없이 카메라→LED 폐루프를 완성하고, **왜 AI 를 넣기 전에 이것을 먼저 만드는지**
설명할 수 있다.

## 1. 왜 AI 없이 먼저 만드는가

모듈 4 에서 VLM 이 이상하게 굴 때, 원인이 **모델인지 배선인지** 어떻게 아는가?

같은 배선 위에서 확실히 동작하는 정책이 있으면 구분된다. 없으면 모든 실패가
모델 탓으로 오인된다. 게다가 여기서 잰 지연이 **AI 도입 비용의 기준선**이 된다.

## 2. 첫 실행

```bash
./host/vs2_demo.py --steps 30 --lock
```

**예상 출력:**
```
[0019] orange #ff9900 56% 중앙 (채도 79, 밝기 89)  →  on #ff9900 @239
=== 종단 지연 (µ2.3) ===
  capture      29.5 ms
  extract       3.6 ms
  decide        0.0 ms
  actuate       0.1 ms
  합계           33.3 ms   30.0 fps
```

**읽는 법:**
- 촬영이 예산의 **88%** 다. 29.5ms 는 30fps 스트림의 프레임 간격 — 파이프라인이
  아니라 **센서 주기가 한계**라 줄일 여지가 없다.
- **판단이 0.0ms** 다. 규칙 기반이라 사실상 공짜다.
  **이 칸이 모듈 4 에서 수백~수천 ms 로 바뀐다.** 그 차이가 AI 의 비용이다.

## 3. 핵심 실습 — 자동노출이 LED 를 지운다

LED 를 켜고 끄며 카메라가 그것을 보는지 잰다.

```python
import sys, time; sys.path.insert(0,'host')
import numpy as np, cv2
from blink import Arduino
from perception import open_source

def avg(cam, n=10):
    return np.mean([cam.read().image.astype(np.float32) for _ in range(n)], axis=0)

with Arduino('/dev/ttyACM0', verbose=False) as a, \
     open_source("argus:0", width=1280, height=720) as cam:
    a.send("RGB 255 255 255"); a.send("LEVEL 255")
    a.send("OFF"); time.sleep(2); off = avg(cam)
    a.send("ON");  time.sleep(2); on  = avg(cam)
    a.send("OFF")

diff = on.mean(axis=2) - off.mean(axis=2)
blur = cv2.GaussianBlur(diff, (21, 21), 0)
_, vmax, _, loc = cv2.minMaxLoc(blur)
print(f"전역 차이   : {on.mean() - off.mean():+.2f}")
print(f"국소 최대   : {vmax:+.2f} @ {loc}")
print(f"노이즈(std) : {diff.std():.2f}")
```

**실제 관측값:**
```
전역 차이   : +0.02        ← LED 를 최대로 켰는데 화면 평균이 안 변한다
국소 최대   : +57.52 @ (497, 393)
노이즈(std) : 10.72        → 신호/노이즈 5.4배
```

### 이것이 설계를 바꾼다

**Argus 자동노출이 전역 밝기를 상쇄한다.** 화면이 밝아지려 하면 노출을 줄여
평균을 원위치시킨다.

따라서 **전체 프레임 평균 밝기를 특징으로 쓰면 LED 가 보이지 않는다.**
원래 계획서에는 "평균 밝기"가 특징으로 적혀 있었다. 그대로 갔다면
"카메라가 LED 를 못 본다" 는 **틀린 결론**에 도달했을 것이다.

**해결:** 관심영역(ROI) 안의 **색상(hue)** 을 본다. 색조는 노출 변화에 견고하다 —
AE 가 바꾸는 것은 밝기이지 색조가 아니다.

## 4. 특징 추출 읽기

```python
from perception import SyntheticSource, patch
from control import extract

img = SyntheticSource(patch(fg=(230, 20, 20))).open().read().image
print(extract(img).describe())
```

**예상:** `red #ff0000 44% 중앙 (채도 233, 밝기 114)`

### 왜 최빈값인가

```python
from control import classify_hue
print(classify_hue(2), classify_hue(175))    # 둘 다 red
```

빨강은 hue 0 근처와 179 근처로 **갈라진다.** 평균을 쓰면 (2+175)/2 = 88.5,
정확히 **청록**으로 오판한다. 그래서 히스토그램 최빈값을 쓴다.

## 5. 핵심 실습 — 출력이 떨린다

```bash
./host/vs2_demo.py --steps 20 --lock
```

이력(hysteresis)을 끄면 (`MirrorColorPolicy(hue_step=0, level_step=0)`):

**실제 관측:** 장면이 정지해 있는데도 **20스텝 중 18회** 명령 전송.

센서 노이즈로 색조가 프레임마다 한두 단위씩 흔들리고, 정책이 충실히 따라간다.
**LED 가 미세하게 깜빡이고** 시리얼이 붐빈다.

| 시도 | 20스텝 중 전송 |
|---|---|
| 원본 | 18회 |
| 양자화 | 11회 |
| **이력** | **2회** |

### 양자화만으로 왜 부족한가

값이 스텝 경계 위에서 진동하면 **양자화 결과도 함께 진동한다.**
직전에 **내보낸** 값과 비교하면 고정된 경계가 없어져 진동이 통과하지 못한다.

로그에서 동작이 보인다 — 관측색은 `#ffdd00` ↔ `#ffcc00` 로 흔들리는데
명령색은 `#ffdd00` 에 머문다.

> **판단의 분해능을 관측의 신뢰도에 맞춘다.** 정확도를 버리는 게 아니라,
> 노이즈를 증폭하지 않는 것이다. 모듈 4 에서 VLM 출력에도 같은 원리를 쓴다.

## 6. 측정 지점이 낡으면 멀쩡한 것도 고장나 보인다

앞 실습에서 LED 위치를 좌표로 적었다.

```python
CX, CY, H = 558, 323, 90        # 이 숫자는 오늘만 맞다
```

카메라를 조금 움직이거나 LED 배선을 다시 하면 **그 좌표는 배경을 가리킨다.**
그런데 프로그램은 오류를 내지 않는다. 배경의 색을 성실히 측정해서 보고할 뿐이다.

실제로 이 교재를 만들며 겪은 일이다. 무지개가 도는데 측정값은 색조 4~20에
머물러 있었다. LED 가 고장난 것처럼 보였지만, **좌표가 낡았을 뿐 LED 는 멀쩡했다.**
매 프레임 가장 밝고 진한 지점을 찾아 다시 재자 색상환이 그대로 나왔다.

```
고정 좌표 (558, 323)  →  색조 20, 11, 4, 7, 11, 13, 19      "안 돈다"
매번 탐색              →  색조 37, 59, 73, 95, 107, 7, 10     정상
```

### 대상을 찾아서 재라

`host/verify_rgb.py` 가 좌표를 박지 않는 이유가 이것이다. LED 소등/점등을
차분해 **매번 위치를 먼저 찾고** 나서 색을 잰다.

```python
off = average(cam);  ard.send("ON");  on = average(cam)
diff = cv2.GaussianBlur(on.mean(axis=2) - off.mean(axis=2), (21, 21), 0)
_, vmax, _, loc = cv2.minMaxLoc(diff)      # 여기가 LED 다
```

> **이 모듈의 주제와 같은 이야기다.** 전역 밝기로 재면 자동노출이 상쇄해서
> "LED 가 안 보인다" 는 틀린 결론에 도달한다. 낡은 좌표로 재면 "색이 안 바뀐다" 는
> 틀린 결론에 도달한다. **무엇을 어떻게 재는지가 결론을 만든다.**

## 7. 변화 시에만 전송하는 이유

`ControlLoop` 은 명령이 **바뀔 때만** 액추에이터를 부른다.
모듈 1 의 의도된 실패 실습에서 봤듯, 같은 `BLINK` 를 반복 전송하면
**점멸 위상이 리셋되어 끊겨 보인다.** 최적화가 아니라 **정확성 요구사항**이다.

## 의도된 실패 실습

1. **전역 밝기를 특징으로 써보기**: `extract` 를 고쳐 ROI 대신 전체 평균을 쓴다.
   LED 를 켜도 반응하지 않는 것을 확인한다.
2. **hue 평균 쓰기**: 최빈값 대신 평균으로 바꾸고 빨간 물체를 비춘다.
   초록으로 판정되는 것을 본다.
3. **이력 끄기**: `hue_step=0, level_step=0` 으로 두고 정지 장면에서
   전송 횟수를 센다.
4. **좌표를 낡게 만들기**: 6절의 고정 ROI 로 색을 측정하면서 **카메라를 몇 cm
   움직인다.** 측정값이 LED 와 무관해지는데도 프로그램은 오류 없이 계속 도는 것을
   확인한다. 그 뒤 `verify_rgb.py` 처럼 매번 탐색하도록 바꿔 다시 잰다.
