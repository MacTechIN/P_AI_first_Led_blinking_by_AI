# 모듈 7 — 30분 실습: 돌려 보고, 무너뜨려 보고, 한 번 진단한다

**장비 0원, 30분.** 노트북 한 대면 된다. 카메라도 아두이노도 서버도 없다.

목표는 숙달이 아니라 **개념을 손으로 한 번 만져 보는 것**이다. 네 가지만 남으면
된다.

> ① 루프는 닫혀 있다 ② 환경이 변하면 판단이 무너진다
> ③ 성공 신호는 작동의 증거가 아니다 ④ 적어두지 않은 것은 지켜지지 않는다

## 시간표

| 시간 | 하는 일 | 명령 |
|---|---|---|
| 5분 | 정상 장비를 본다 | `./host/sim_demo.py --scenario basics` |
| 5분 | 환경이 변하면 | `./host/sim_demo.py --scenario dusk` |
| 5분 | 대본이 곧 골든셋 | `./host/scenario_check.py` |
| 10분 | 결함 하나를 진단 | `./host/sim_demo.py --fault random --seed <팀번호>` |
| 5분 | 정리 | 아래 "남길 것" |

---

## 1단계 (5분) — 루프가 닫혀 있다

```bash
./host/sim_demo.py --scenario basics
```

왼쪽이 카메라가 보는 색지, 오른쪽 불빛이 정책이 켠 LED 다. **둘이 같은 장면에
있다** — 명령이 다음 프레임에 보인다. 이것이 제어 루프다.

보면서 확인할 것 두 가지:

- 색지가 바뀐 **그 스텝에만** `*` 표시가 뜬다. 같은 판단이면 보내지 않는다.
- 빨강만 점멸한다. 규칙이 그렇게 정해져 있다.

끝에 나오는 줄을 외워 둔다 — **명령 전송 3회 / 240 스텝.**

## 2단계 (5분) — 환경이 변하면 무너진다

```bash
./host/sim_demo.py --scenario dusk
```

색지는 초록 그대로다. **조명만 꺼진다.** 어느 순간 "물체 없음" 으로 바뀐다.

한 줄로 답해 본다: **색이 사라진 것인가, 색을 믿지 못하게 된 것인가?**

(둘째가 맞다. 어두우면 색조는 노이즈가 되므로 특징 추출이 일부러 포기한다.
포기하는 것과 틀리게 답하는 것 중 어느 쪽이 나은지가 설계 결정이다.)

## 3단계 (5분) — 대본이 곧 골든셋

```bash
./host/scenario_check.py
```

`scenarios/*.json` 은 장면만이 아니라 **그 시각에 무엇이 맞는지**도 함께 적고
있다. 그래서 장면이 그대로 회귀 시험이 된다. 9/9 통과를 확인한다.

이제 결함을 넣어 본다.

```bash
./host/scenario_check.py --quiet --fault stale-roi       # 1/9  — 잡는다
./host/scenario_check.py --quiet --fault no-hysteresis   # 9/9  — 못 잡는다
```

**둘째 줄이 이 실습의 핵심이다.** `no-hysteresis` 는 명령을 쏟아내는 실제 고장인데
대본은 전부 통과시킨다. 기대에 "무엇이 보이는가" 만 적고 "얼마나 자주 보내는가" 는
적지 않았기 때문이다.

> 골든셋은 **적어둔 것만** 지킨다. 적지 않은 회귀는 조용히 통과한다.

## 4단계 (10분) — 결함 하나를 진단한다

강사가 팀마다 다른 시드를 준다. **무엇이 들어갔는지는 알려주지 않는다.**

```bash
./host/sim_demo.py --fault random --seed 17 --steps 60
```

증상 한 줄만 뜬다. 계층을 순서대로 잘라 나간다.

| 계층 | 질문 | 재는 법 |
|---|---|---|
| 센서 | 프레임에 정보가 있나 | 표준편차 · 건전성 검사 |
| 특징 | 보는 자리가 맞나 | 같은 프레임을 올바른 ROI 로 다시 본다 |
| 판단 | 정지 장면에서 조용한가 | `--still` 로 전송 횟수를 센다 |
| 구동 | 명령 = 발광인가 | 명령한 색과 **발광한 색**을 나란히 적는다 |
| 모델 | 전부 실패인가 일부인가 | `policy.stats` 의 requests 대 failed |

마지막 줄만 외워도 된다 — **전부 실패하면 전송 계층, 일부만 실패하면 계약이다.**

```python
from sim import build_rig
rig = build_rig("의심하는 결함 이름")      # 가설을 직접 켜 본다
with rig.source as src:
    obs = src.read()
    print(obs.image.std())                 # 센서
    print(rig.extractor(obs.image))        # 특징
    print(rig.world.emitted())             # 구동
```

**규칙**: `--reveal` 과 `sim/faults.py` 는 둘 다 답지다. 답을 말한 뒤에 연다.

| | |
|---|---|

마지막 줄이 빈 보고서는 반쪽이다. 원인을 찾는 것보다 **다음에 자동으로 잡히게
만드는 것**이 일의 끝이다.

## 더 해볼 것 (시간이 남으면)

1. **건전성 검사를 꺼 본다**: `flat-frame` 결함에서 `source.check_health = False`.
   예외가 사라지고 **아무 오류 없이 "물체 없음" 만** 계속 나온다. 어느 쪽이 더
   위험한가?
2. **대본을 하나 써 본다**: `scenarios/` 에 JSON 한 장을 추가한다. 코드는 건드리지
   않는다. 기대를 일부러 틀리게 적고 `scenario_check.py` 가 잡는지 본다.
3. **올바른 배선을 본다**: `./host/sim_demo.py --per-channel-resistor` — 저항을
   채널마다 두면 노랑이 노랑으로 나온다.

## 연습 문제

1. `/health` 가 ok 를 돌려주는데도 추론이 전부 실패하고 있었다. 이 상태를
   **LED 만 보고** 알아챌 수 있는가? 알아챌 수 없다면 무엇을 추가해야 하는가?
2. 대본이 `no-hysteresis` 결함을 9/9 로 통과시켰다. 왜인가? 그리고 이 고장을
   대본이 잡게 하려면 기대에 무엇을 추가해야 하는가?
3. 진단 보고서의 "재발 방지" 칸에 "다음부터 주의한다" 라고 쓰면 왜 틀린
   답인가? 이 저장소에서 그 칸을 제대로 채운 사례를 하나 찾아 근거로 드시오.

## 교훈

> **성공 신호는 작동의 증거가 아니다.** 장치 파일이 있는 것, `/health` 가 ok 인
> 것, 스키마를 통과한 것, 골든셋이 9/9 인 것 — 넷 다 이 저장소에서 한 번씩
> 사람을 속였다.
