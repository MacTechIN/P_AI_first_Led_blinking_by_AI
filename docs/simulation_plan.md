# 실습 시뮬레이션 환경 계획 — 여러 사람이 동시에 실습하려면

실물 장비는 한 벌인데 수강생은 여럿이다. 이 문서는 그 간격을 메우는 계획이다.
전제는 `docs/curriculum.md`, 슬라이드 번호는 `docs/lecture/deck/` 기준.

---

## 0. 무엇이 모자란가

실습 1회(수강생 20명 / 4~5인 팀 4~5개) 기준으로 **부족한 자원은 셋**이다.

| 자원 | 보유 | 동시 사용 가능 수 | 왜 늘릴 수 없나 |
|---|---|---|---|
| CSI 카메라 | 1 | 1 | Argus 데몬이 센서를 독점한다 |
| `/dev/ttyACM0` | 1 | **1** | 한 프로세스만 포트를 잡을 수 있다 |
| VLM (GPU) | 1 | **1** | `--parallel 1` 이 아니면 첫 요청에서 죽는다 |

그런데 이 셋은 **교재가 "반드시 직접 재 보라" 고 말한 바로 그 셋**이다. 그래서
시뮬레이션의 설계 목표가 하나로 정해진다.

> **시뮬레이터는 잘 되는 것을 재현하는 물건이 아니라, 기록된 실패를 재현하는
> 물건이다.** 잘 되는 것만 재현하면 해피패스만 가르치게 되고, 그것은 이
> 커리큘럼이 하지 않기로 한 일이다.

---

## 1. 이미 있는 이음매

새로 만들 것이 생각보다 적다. 아래는 전부 지금 돌아간다.

| 이음매 | 위치 | 시뮬레이션에서의 역할 |
|---|---|---|
| `FrameSource` 추상화 | `perception/sources.py` | 카메라를 통째로 갈아끼운다 |
| `SyntheticSource` + `solid/patch/moving_patch/flat` | 같은 파일 | 장면을 코드로 만든다 |
| `ImageFileSource` | 같은 파일 | 녹화한 현장을 재생한다 |
| `NullActuator` | `control/actuator.py` | 명령을 기록만 하고 보내지 않는다 |
| `status: planned` + `transport: null` | `capabilities/*.json` | 없는 장치를 선언만으로 다룬다 |
| `StepResult` 단계별 계측 | `control/loop.py` | 어디서 느린지 수강생이 직접 본다 |
| 골든셋 + `host/evaluate.py` | `golden/`, `control/evaluate.py` | 채점이 이미 자동이다 |

`./host/vs2_demo.py --source synthetic --dry-run` 은 **지금도 장비 없이 돈다.**
출발점은 0 이 아니라 여기다.

## 2. 계층 구조 — 무엇을 어디서 돌리나

```
  Tier 0   수강생 노트북 (인원수만큼)      장비 0원
           합성 장면 + 가상 LED + VLM 리플레이 → 루프 전체가 닫힌다

  Tier 1   팀별 아두이노 + RGB LED (팀당)  팀당 약 3만원
           판단은 Tier 0 그대로, 출력만 진짜 → "화면 밖" 을 손으로 만진다

  Tier 2   Jetson + 카메라 + VLM (공용 1벌)
           큐에 제출하면 60초간 실물에서 돌고 영상·로그가 돌아온다
```

핵심은 **Tier 0 에서 통과한 정책을 그대로 Tier 2 에 제출**한다는 것이다.
정책 코드가 계층을 건너도 바뀌지 않아야 하고, 그것이 `Policy` 인터페이스가
이미 보장하는 성질이다.

## 3. 만들 것 — 여섯 조각

### 3.1 가상 액추에이터: LED 가 다음 프레임에 보인다 ★

지금의 `NullActuator` 는 명령을 삼킨다. 그래서 루프가 닫히지 않는다.
`SimActuator` 는 명령 받은 색을 **장면에 그려 넣고**, 다음 프레임에서 카메라가
그것을 본다.

```
정책 → RGB 120 0 0 → SimActuator → 장면의 LED 좌표에 색을 칠함
                                 → 다음 프레임 → 특징 추출 → 정책
```

이것 하나로 노트북에서 **제어 루프 전체가 관측 가능**해진다. 색 미러링,
히스테리시스, 명령 변화시에만 전송하는 규칙까지 전부 눈으로 보인다.

여기에 실물의 성질을 넣는다. 공통 애노드 반전, 공통 저항 경쟁(빨강이 이김),
밝기의 비선형성. **보정하지 않은 상태가 기본값**이어야 한다 — 수강생이
`RGB 255 255 0` 을 넣었을 때 순수 빨강이 나와야 모듈 3 의 교훈이 재현된다.

### 3.2 장면 대본 (Scenario)

JSON 한 장이 한 장면을 만든다. 팀마다 다른 대본을 주면 과제가 달라진다.

```json
{ "name": "line-A", "size": [640, 480], "fps": 30,
  "led":   { "at": [520, 300], "radius": 18 },
  "events": [
    { "t": 0.0, "set": { "card": "red" } },
    { "t": 3.0, "set": { "card": "green" } },
    { "t": 6.0, "enter": { "person": "left", "speed": 120 } },
    { "t": 9.0, "set": { "light": 0.4 } }
  ] }
```

대본은 **기대 출력을 함께 가진다**. 그래서 장면이 곧 골든셋이 된다.

### 3.3 결함 주입 — 이 계획의 중심 ★★

플래그 하나가 기록된 실패 하나를 되살린다. 수강생의 과제는 "고쳐라" 가 아니라
**"무엇이 틀렸는지 측정으로 찾아내라"** 이다.

| 플래그 | 재현하는 실패 | 수강생이 발견해야 하는 것 | 원 기록 |
|---|---|---|---|
| `--fault flat-frame` | 모든 픽셀이 같은 값인 `/dev/video0` | 장치는 있는데 데이터가 없다 | `project_0_camtest.md` |
| `--fault health-ok-dead` | `/health` 는 ok, 요청은 죽음 | 성공 신호 ≠ 작동 | `vlm-on-orin-nano.md` |
| `--fault schema-drift` | 검증기가 5건 중 4건 거부, 폴백이 은폐 | `policy.stats` 를 봐야 한다 | ADR-0009 |
| `--fault slow-vlm` | 추론 3초, 루프 34ms | 동기 호출이면 제어가 죽는다 | ADR-0008 |
| `--fault autoexposure` | 카메라가 밝기를 되돌림 | 측정이 보정에 먹힌다 | `led-camera-detection.md` |
| `--fault stale-roi` | ROI 하드코딩, 무지개가 멈춰 보임 | 멀쩡한 것이 고장나 보인다 | 모듈 3 연습문제 |
| `--fault no-hysteresis` | 정지 화면 20장에 명령 18회 | 노이즈만으로 떨린다 | ADR-0007 |

**강사는 어떤 결함을 넣었는지 말하지 않는다.** 7종 중 하나를 무작위로 켜고
"이 팀의 장비는 뭔가 이상하다. 측정으로 밝혀라" 로 시작한다. 이것이 모듈 6
(안전·평가)의 실습 형태가 된다.

### 3.4 VLM 기록·재생 프록시 ★

GPU 는 하나고 `--parallel 1` 이다. 20명이 동시에 때리면 큐가 분 단위로 밀린다.

- **기록**: 실습 전에 모든 장면·모든 각도에 대해 한 번씩 실제 응답을 받아
  `(이미지 해시 → 응답)` 으로 저장한다.
- **재생**: 수강생 노트북의 `ReplayVlmClient` 가 그 표를 읽는다. 지연까지
  재현하므로 비동기 구조의 필요성이 그대로 보인다.
- **부수 효과**: 응답이 결정적이 되어 골든셋 채점이 재현 가능해진다. 실습
  끝나고 집에서도 그대로 돌아간다.
- 표에 없는 이미지는 "없음" 을 반환한다 — `action: "none"` 이 합법인 이유를
  수강생이 자기 손으로 만나게 된다.

### 3.5 실물 제출 큐 (Tier 2)

포트도 카메라도 하나뿐이라는 제약이 그대로 아키텍처가 된다.

```bash
./host/submit.py --policy teamA/policy.py --scenario line-A --seconds 60
#  → 대기 3번째 … 실행 중 … 완료
#  → runs/2026-10-18T22-30_teamA/{video.mp4, timings.csv, commands.log, report.json}
```

작업은 **직렬로** 돈다. 수강생은 "왜 동시에 못 하나" 를 묻게 되고, 그 답이
강의 2-1 의 자원 경합 이야기와 같다. 제약을 숨기지 말고 보여준다.

안전: 제출된 정책은 역량 선언(`capabilities/*.json`)을 통해서만 장치에 닿는다.
범위 밖 명령은 펌웨어가 막는다 — 수강생 코드가 하드웨어 경계를 넘을 수 없다는
것이 ADR-0003 의 주장이고, 이 실습이 그 주장의 증명이다.

### 3.6 숨은 골든셋 리더보드

- **공개 세트**: 팀이 개발 중 자유롭게 돌린다.
- **숨은 세트**: 채점 때만 돈다. 공개 세트에 과적합한 팀은 여기서 떨어진다.
- 점수는 정확도 하나가 아니라 **정확도 · 지연 · 전송 횟수 · 폴백 비율** 넷을
  함께 보여준다. 하나만 올리면 다른 게 내려가는 것을 표로 보게 만든다.

## 4. 실습 진행 시나리오 (90분)

| 시간 | 내용 | 계층 |
|---|---|---|
| 0~10분 | 각자 노트북에서 `sim_demo.py` 실행. 루프가 도는 것을 본다 | 0 |
| 10~30분 | **결함 주입 과제.** 팀마다 다른 결함. 측정으로 범인을 찾는다 | 0 |
| 30~50분 | 규칙 정책을 짠다. 공개 골든셋으로 자가 채점 | 0 |
| 50~65분 | VLM 재생으로 바꿔 돌린다. 규칙과 A/B 비교표를 채운다 | 0 |
| 65~80분 | 팀별 아두이노에 연결. 같은 정책, 진짜 LED | 1 |
| 80~90분 | 실물 큐에 제출. 영상으로 결과 확인 · 리더보드 | 2 |

Chapter 5 워크시트 ③(규칙/AI 판정)이 30~50분 구간의 산출물이 되고,
⑤(골든셋 설계)가 숨은 세트에 들어갈 사례가 된다. **워크시트가 곧 코드가 된다.**

## 5. 구현 순서

| 단계 | 내용 | 없으면 생기는 일 |
|---|---|---|
| **S-1 ✅** | `SimActuator` + 가상 LED 렌더링 | 루프가 닫히지 않아 아무것도 관측 못 함 |
| S-2 | 장면 대본 로더 + 기대 출력 | 팀마다 다른 과제를 줄 수 없음 |
| **S-3 ✅** | 결함 주입 **8종** | 해피패스만 가르치게 됨 — **가장 중요** |
| S-4 | VLM 기록·재생 | GPU 큐에서 실습이 멈춤 |
| S-5 | 제출 큐 + 녹화 | 실물 경험이 강사 시연으로 축소됨 |
| S-6 | 숨은 세트 · 리더보드 | 과적합을 가르칠 기회를 놓침 |

S-1 ~ S-3 까지면 **장비 0원으로 90분 실습이 성립**한다. S-4 이후는 질을 올린다.

## 6. 하지 않을 것

- **물리 엔진**: 빛의 산란이나 렌즈 왜곡을 정밀하게 모사하지 않는다. 교재가
  가르치는 것은 광학이 아니라 **구조**다.
- **실물을 대체하는 척하기**: 시뮬레이터는 실물의 근사치가 아니라고 명시한다.
  수강생이 "시뮬에서 됐는데요" 라고 말하는 순간이 바로 4-2 의 PoC 실패
  이야기를 꺼낼 자리다. 그 말이 나오도록 설계한다.
- **결함을 고쳐 두기**: 공통 애노드·공통 저항·자동 노출은 **켜진 채로** 둔다.
  잘 되는 시뮬레이터는 쓸모가 없다.

## 부록 — S-1 에서 재 보고 알게 된 것 (2026-10-19)

계획을 쓸 때 **"LED 를 ROI 안에 두면 루프가 자기 출력을 먹는다"** 고 적었다.
만들고 재 보니 **그것만으로는 일어나지 않았다.**

| 반경 | LED 위치 | 색지를 치운 뒤 | |
|---|---|---|---|
| 24px (기본) | ROI 밖 | 물체 없음 | 정상 |
| 24px | ROI **안** | 물체 없음 | **예상과 다름** |
| 70px | ROI 밖 | 물체 없음 | 정상 |
| 70px | ROI **안** | 계속 "초록" | 자기 출력을 먹는다 |

이유는 시뮬레이터가 재현한 성질 두 개였다. 코어가 흰색으로 포화해 채도 문턱에
걸러지고, 남은 테두리는 색지(ROI 의 49%)에 **면적으로 진다.** 반경을 키워
테두리가 `MIN_COVERAGE` 를 넘겨야 비로소 뒤집힌다.

예상이 틀렸다는 것보다 **무엇이 막고 있었는지가 더 쓸모 있는 수업 재료**다.
`--led-in-roi --led-radius 70 --cards green,none` 으로 재현하고,
세 조건을 `tests/test_sim.py` 가 고정한다.

## 부록 — S-3 에서 재 보고 알게 된 것 (2026-10-19)

결함을 넣었다고 증상이 나오지는 않았다. 여덟 개를 하나씩 돌려 확인했고,
둘이 기록과 달랐다.

**`polarity` 는 이득 보정까지 되돌려야 했다.** 극성만 뒤집으면 빨강 명령에
노랑(122,120,13)이 나왔다. 기록된 증상은 청록이다. 원인은 순서였다 — 극성
버그는 이득 보정보다 **먼저** 있었고, 기록은 보정 전 상태에서 관측된 것이다.
이득을 255 로 되돌리자 기록 세 줄이 그대로 재현됐다: 흰색 → 소등,
`RGB 255 0 0` → (0,230,25), `RGB 0 0 0` → 점등.

**모델 계층 두 결함의 지문이 같은 칸에 쌓인다.** `VlmPolicy._infer` 는
`client.ask()` 가 던지는 `VlmError` 를 전부 `failed` 로 센다. 전송 실패든 계약
위반이든 구별되지 않는다. 그래도 가를 수는 있다 — 죽은 서버는 **전부**
실패하고(20/20), 어긋난 계약은 **일부만** 실패한다(16/20, 성공 4). 비율이
지문이다. 실습서의 진단 절차 마지막 줄이 이것이다.

**노이즈는 숫자를 맞추려 하지 않았다.** `no-hysteresis` 는 ADR-0007 의 18/20 을
목표로 했으나, 물리적 근거가 있는 값(읽기 노이즈 σ=4, 흔들림 ±1px)에서
**11/20** 이 나왔다. 정상은 1/20 이므로 교훈은 그대로 선다. 더 키우면 근거
없는 숫자 맞추기가 되므로 멈추고 차이를 적는다. 시뮬레이터의 색지는 단일
색이라 **지배 색조가 아예 움직이지 않고**, 면적만 흔들린다 — 실물에서는 둘 다
흔들린다. 그 차이가 11 과 18 의 간격이다.
