# 숨은 골든셋과 네 칸짜리 점수 (2026-10-19)

S-6 의 기록. 공개 세트만으로 채점하면 무엇을 놓치는지, 그리고 그것을 알아내는
과정에서 평가 자체가 두 번 틀렸던 이야기.

## 왜 숨은 세트인가

공개 세트는 팀이 개발 중 마음껏 돌린다. 그러면 거기에 맞추게 된다 — 나쁜
의도가 아니라 그게 피드백이 있는 유일한 곳이기 때문이다. 숨은 세트는 채점
때만 돌아서 **맞출 수 없는 기준**을 하나 남겨 둔다.

저장소의 `scenarios/hidden/` 은 **구조의 본보기**다. 읽을 수 있는 것은 숨은
것이 아니므로, 실제 수업에서는 강사가 자기 것을 따로 둔다.

| 대본 | 무엇을 노리나 |
|---|---|
| `offcolour` | 주황·보라·청록. 공개 세트에 없던 색 |
| `twilight` | 어둡지만 **색은 아직 유효하다.** 포기 문턱을 올린 정책이 걸린다 |
| `flicker` | 색이 자주 바뀐다. 이력을 없앤 정책이 전송 칸에서 드러난다 |

## 점수를 하나로 합치지 않는다

```
팀          정책                     공개     숨은      지연        전송      모델
chatty     MirrorColorPolicy      9/9    12/12    35.8ms   12.5/100       —
example    MirrorColorPolicy      9/9    12/12    34.8ms    2.7/100       —
tuned      TunedPolicy            9/9     9/12    34.6ms    2.2/100       —
vlm        VlmPolicy              9/9     3/12    31.4ms    2.5/100      27%
```

**열을 하나씩만 보면 매번 다른 팀이 1등이다.** 정확도만 보면 chatty 가 공동
1등이고 전송은 다섯 배다. 전송만 보면 tuned 가 1등이고 숨은 세트에서 무너진다.
지연만 보면 vlm 이 1등인데 모델이 실제로 말한 것은 27% 뿐이다.

`모델` 칸은 모델이 **쓸 수 있는 말을 한** 스텝의 비율이다. `action: "none"` 은
세지 않는다 — 판단을 내놓지 않은 것이기 때문이다.

## 평가가 두 번 틀렸다

### ① 기대가 정책이 아니라 인지를 검사하고 있었다

과적합시킨 `tuned` 가 숨은 세트를 **12/12 로 통과했다.** 기대값이 `color` 만
보고 있었고, 그것은 `extract()` 가 내는 값이라 **정책이 무엇을 하든 바뀌지
않는다.** 정책은 주황을 보고 LED 를 껐는데, 채점은 "주황이 보였는가" 만 물었다.

`action` 과 `cmd_colour`(정책이 실제로 켠 색)를 기대에 넣고 나서야 9/12 가 됐다.

S-4 에서 빈 기록이 9/9 를 통과했던 것과 **똑같은 실수**다. 그때는 폴백이
모델을 가렸고, 이번에는 인지가 판단을 가렸다. `observe()` 가 이제 세 층을
구별해서 낸다 — 인지(`color`·`zone`), 판단(`action`·`cmd_colour`),
모델(`vlm_*`). 섞으면 엉뚱한 것을 검사하게 된다.

### ② "폴백 비율" 이 0% 로 나왔다

`VlmPolicy.last_decision` 은 모델이 `none` 을 답해도 기록으로 남는다. 그래서
"판단이 있었는가" 로 세면 100% 가 되는데, 실제로는 아무 말도 하지 않은 것이다.
`action != "none"` 인 스텝만 세도록 고쳤다. 27% 가 나왔고, 이는 기록된 응답의
69% 가 `none` 이라는 실측과 맞는다.

## vlm 팀의 3/12 — 세 가지가 겹쳤다

숨은 세트에서 무슨 일이 일어났는지 `--detail` 로 보면:

1. **기록이 엉뚱한 장면에 답했다.** `twilight` 의 초록은 `dusk` 의 초록과
   가까워 **53회 적중**했다. 그런데 `dusk` 에서 모델이 한 답은 `off` 였다.
   본 적 없는 장면에 본 적 있는 답을 붙인 것이고, 최근접 탐색이 지나치게
   너그러우면 이렇게 된다.
2. **`none` 은 직전 명령을 유지한다.** `offcolour` 는 58회 빗나가 모두
   `none` 이 됐고, 그래서 ①에서 붙은 `off` 가 **그대로 남았다.** 다음 대본까지.
3. **모델이 원래 말을 잘 안 한다.** 기록의 69% 가 `none` 이다.

셋 다 설계대로 동작한 결과다. 그런데 합쳐 놓으면 "불이 꺼진 채 아무 일도
일어나지 않는" 상태가 된다. **각 부품이 옳게 동작해도 조합이 틀릴 수 있다** 는
것을, 숨은 세트가 아니었으면 보지 못했을 것이다.

## 쓰는 법

```bash
./host/scenario_check.py                 # 팀이 개발 중 — 공개 세트만
./host/leaderboard.py                    # 채점 — 공개 + 숨은
./host/leaderboard.py --detail           # 어느 사례가 왜 떨어졌는지
```

숨은 세트를 개발 중에 돌리기 시작하면 그것도 공개 세트가 된다.
