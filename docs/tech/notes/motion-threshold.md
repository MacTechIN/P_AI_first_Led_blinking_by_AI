# 예제 2 측정 — 움직임 임계값과 자동보정 (2026-09-18)

시간 축이 들어오면 새 문제가 생긴다. **무엇을 "변화" 로 볼 것인가.**

## 임계값은 추측하지 않고 잰다

순서는 하나뿐이다. **정지 장면의 노이즈를 먼저 재고**, 알려진 변화에 대한 반응을
재고, 둘을 가르는 값을 고른다.

```bash
./host/measure_motion.py --frames 60
```

정지 장면(LED 소등, 아무도 움직이지 않음)과 알려진 변화(LED 점등/소등)를 각각 잰다.
LED 를 쓰는 이유는 **우리가 정확히 언제 변했는지 알기 때문**이다.

## 결과 — 자동보정 고정

| | 평균 | p95 | 최대 | n |
|---|---|---|---|---|
| 정지 (노이즈) | — | **0.300** | — | 59 |
| LED 상태 전환 | **3.245** | 3.838 | 3.906 | 12 |

**여유 10.8배.** 임계값 0.6(노이즈 p95 × 2)에서 오경보 0%, 검출 100%.

| 임계값 | 오경보 | 검출 |
|---|---|---|
| 0.601 (p95×2) | 0.0% | 100% |
| 0.901 (p95×3) | 0.0% | 100% |
| 1.501 (p95×5) | 0.0% | 100% |

셋 다 완벽하므로 **가장 낮은 값**을 고른다. 낮을수록 민감하고, 오경보가 없는 한
민감한 편이 낫다.

## 자동보정을 켜면 — 직관과 반대의 결과

| | 노이즈 p95 | LED 전환 신호 |
|---|---|---|
| 고정 (`aelock`·`awblock`) | 0.300 | 3.245 |
| **자동보정 켜짐** | **0.483** | **10.505** |

노이즈가 60% 오른 것은 예상대로다. 노출이 미세하게 조정되면 장면이 그대로여도
픽셀이 바뀐다.

**놀라운 것은 신호가 3.2배 커진 것이다.** 좋아 보이지만 그 반대다.

### 왜 커지는가, 그리고 왜 나쁜가

LED 가 켜지면 자동노출이 **화면 전체를 다시 노출한다.** 실제로 변한 것은 LED 하나인데
**모든 픽셀이 바뀐다.** 검출기는 그것을 "거대한 움직임" 으로 읽는다.

즉 자동보정은 신호를 키운 것이 아니라 **왜곡한 것**이다. 결과적으로 검출기는
두 가지를 구별하지 못하게 된다:

- 무언가 **움직였다**
- 카메라가 **노출에 대한 생각을 바꿨다**

실제 운용에서 이것이 오경보가 된다. 구름이 지나가거나 형광등이 깜빡이면,
아무도 움직이지 않았는데 화면 전체가 바뀌고 경보가 울린다.

> **차분 기반 검출에서 `aelock`·`awblock` 은 선택이 아니라 전제다.**

모듈 3 에서 자동노출이 LED 를 **지웠던 것**과 짝을 이룬다. 거기서는 상쇄해서 안
보이게 했고, 여기서는 증폭해서 없는 것을 보이게 한다. **같은 기능이 두 방향으로
측정을 망친다.**

## 경보는 사건이 아니라 상태다

한 프레임이 임계를 넘었다고 켜고 다음 프레임에 끄면 깜빡인다. 사람은 계속
움직이지 않는다 — 걷다가 멈추고 다시 걷는다.

`hold_s`(기본 2초) 동안 새 움직임이 없어도 경보를 유지한다. 모듈 3 의 이력과
같은 문제이고 같은 해법이다.

## 설계에서 정한 것

**첫 프레임은 `None` 을 돌려준다.** 0.0 을 돌려주면 "변화 없음" 과 구별되지 않는다.
비교 대상이 없는 것과 비교했더니 같은 것은 다른 상태다.

**해상도를 160×90 으로 줄여서 잰다.** 속도만이 아니라 **축소가 저역통과 역할**을
해서 화소 단위 노이즈를 눌러준다. 이것도 노이즈 바닥을 낮추는 데 기여한다.

## 재현

```bash
./host/measure_motion.py                # 고정
./host/measure_motion.py --no-lock      # 자동보정 켜고 비교
```
