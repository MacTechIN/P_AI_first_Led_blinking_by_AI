# VS-2 종단 지연 기준선 (µ2.3)

VS-3 에서 VLM 을 넣었을 때 **무엇이 얼마나 비싸졌는지** 비교할 기준.
측정: argus:0 @640×480, ColorRulePolicy, SerialLedActuator, 30 스텝.

| 단계 | 평균 |
|---|---|
| 촬영 (capture) | **30.4 ms** |
| 특징 (extract) | 3.8 ms |
| 판단 (decide) | **0.0 ms** |
| 구동 (actuate) | 0.3 ms |
| **합계** | **34.6 ms** (p95 34.5) |
| 처리율 | **28.9 fps** |

## 읽는 법

- **촬영이 예산의 88% 를 쓴다.** 30.4ms 는 30fps 스트림의 프레임 간격과 같다 —
  즉 파이프라인이 아니라 센서 주기가 한계다. 이 단계는 더 줄일 여지가 거의 없다.
- **판단이 0.0ms 다.** 규칙 기반이라 사실상 공짜다. VS-3 에서 이 칸이
  수백~수천 ms 로 바뀔 것이고, 그 차이가 곧 "AI 를 넣는 비용" 이다.
- 이 수치가 **VS-3 의 설계를 강제한다.** 판단이 초 단위가 되면 34ms 루프에
  넣을 수 없다. 정책 루프(느림)와 제어 루프(빠름)를 분리해야 하며,
  이는 ADR-0001 이 이미 정한 방향이다.

## 명령 전송 횟수

30 스텝 중 **1회**만 전송됐다. 장면이 변하지 않으면 명령도 변하지 않고,
`ControlLoop` 은 바뀐 경우에만 구동한다.

같은 `BLINK` 를 반복 전송하면 펌웨어가 점멸 위상을 리셋해 **눈에 끊겨 보인다.**
그래서 변화 감지는 최적화가 아니라 **정확성 요구사항**이다.

## 재현

```bash
./host/vs2_demo.py --steps 30
./host/vs2_demo.py --source synthetic   # 하드웨어 없이
```
