# RGB LED 배선 진단 및 색상 검증 (2026-09-17)

명령한 색과 **카메라가 실제로 찍은 색**을 대조해 두 가지 하드웨어 문제를
찾아내고 보정한 기록. 둘 다 추측이 아니라 촬영으로 확정했다.

배선: B=9, R=10, G=11 (모두 PWM), 공통 애노드.

## 결과 추이

| 단계 | 일치 | 평균 색조 오차 |
|---|---|---|
| 최초 | 0/6 | 73.5 |
| 차분 측정 도입 | 0/6 | 73.5 |
| **공통 애노드 반전** | 3/6 | 21.2 |
| 포화 화소 제외 | 4/6 | 17.3 |
| AWB/AE 고정 | 3/6 | 16.5 |
| **채널 이득 보정** | **6/6** | **7.7** |

## 문제 1 — 공통 애노드 (극성 반전)

LED 를 촬영한 결과가 결정적이었다:

| 명령 | 실제 발광 |
|---|---|
| `RGB 255 255 255` | **꺼짐** |
| `RGB 255 0 0` | **청록** (R 만 꺼지고 G+B 점등) |
| `RGB 0 0 0` | 점등 |

공통 애노드 모듈은 각 캐소드를 핀이 당기고 공통 단자가 +5V 다. 즉 핀이 **LOW 일
때 점등**한다. `analogWrite` 값을 반전해야 한다 (`255 - duty`).

통계만 봤다면 놓쳤을 것이다. 측정 색조가 명령과 무관하게 ~95 로 고정되어
"측정 실패" 로만 보였다. **사진을 직접 본 것이 전환점이었다.**

## 문제 2 — 공통 전류 제한 저항

극성을 고친 뒤에도 혼합색이 틀렸다. 패턴이 원인을 지목했다:

| 혼합 | 기대 | 실제 |
|---|---|---|
| 노랑 (R+G) | 노랑 | **빨강** |
| 자홍 (R+B) | 자홍 | **빨강** |
| 청록 (G+B) | 청록 | **초록** |

항상 **순방향 전압이 낮은 다이가 이긴다** (적 < 녹 < 청). 전류원이 공유될 때
나타나는 현상이다. 검증 실험:

```
R=255, G=255 →  색조   0  (순수 빨강)
R=120, G=255 →  색조  38  (초록 쪽으로 급전환)
R= 60, G=255 →  색조  58
```

채널마다 저항이 있다면 R=255·G=255 는 노랑(30)이어야 한다. 빨강을 절반 이하로
낮춰야 초록이 드러나는 것은 **전류 경쟁**의 증거다.

### 보정과 진짜 해결책

펌웨어에 채널 이득을 넣어 강한 다이를 억제했다: `GAIN_R=120, GAIN_G=200, GAIN_B=255`.

**이는 우회이지 해결이 아니다.** 하드웨어 해결책은 공통 단자 저항 하나 대신
**R·G·B 각 다리에 저항을 하나씩**(220~330Ω) 두는 것이다. 그렇게 배선하면
세 이득을 모두 255 로 되돌려야 한다.

## 측정 기법에서 배운 것

1. **차분이 필수다.** 절대 프레임의 색조는 ROI 대부분을 차지하는 배경이 지배해,
   명령과 무관하게 한 값(~95)에 고정된다. 소등 기준 차분만이 LED 의 기여를 분리한다.
2. **포화 화소를 빼야 한다.** LED 코어는 어떤 색이든 카메라를 포화시켜 흰색이 된다.
   색 정보는 주변부에만 남는다.
3. **AWB/AE 를 고정해야 한다.** 자동 보정이 켜져 있으면 "LED 색이 변한 것" 과
   "카메라가 해석을 바꾼 것" 을 구별할 수 없다.
   `ArgusSource(wbmode=1, awblock=True, aelock=True)`.
4. **색조는 원형이다.** 빨강은 0 과 179 양끝에 걸쳐 있어 산술 평균이 무너진다.
