# VLM 응답 기록·재생 (2026-10-19)

교실에서 GPU 하나를 스무 명이 나눠 쓸 수 없다 (`--parallel 1`). 그래서 **실습
전에 한 번** 실제 모델에게 묻고, 수강생은 그 표를 읽는다. S-4 의 기록.

## 무엇을 열쇠로 쓰나

프레임을 해싱할 수 없다. 센서 노이즈 때문에 **같은 장면도 두 번 다시 같은
바이트가 아니다.** 8×6 색 썸네일을 열쇠로 쓰고 가장 가까운 것을 찾는다.

측정한 거리:

| 비교 | 거리 |
|---|---|
| 같은 장면, 다른 프레임 (노이즈만) | **0.0010** |
| 초록 vs 파랑 (가장 가까운 다른 쌍) | 0.0632 |
| 빨강 vs 초록 | 0.0827 |
| 빨강 vs 파랑 | 0.0862 |

임계를 **0.02** 로 두었다. 노이즈의 20배, 가장 가까운 다른 장면의 1/3 이다.
처음에 0.055 로 잡았다가 내렸다 — 0.0632 와 너무 가까워 여유가 없었다.

거리가 임계를 넘으면 **답하지 않는다**(`action: "none"`). 느슨하게 맞춰 주면
본 적 없는 장면에도 무언가를 내놓는데, 그것은 모르면서 아는 척하는 것이다.
`stats["misses"]` 가 그 횟수를 센다. 세 대본 453 스텝에서 빗나감 0 이었다.

## 기록한 것

Qwen2.5-VL-3B-Instruct-Q4_K_M, 1.5초 간격, 대본 3개 51건. 평균 2,717~2,925ms.

| 대본 | 색 | 행동 |
|---|---|---|
| basics | red 6 · green 5 · blue 6 — **17/17 정확** | none 13 · blink 3 · off 1 |
| dusk | green 17 — **전부** | none 12 · off 5 |
| sweep | yellow 15 · white 2 | none 10 · off 6 · on 1 |

**색은 거의 완벽하고 행동은 거의 쓸모없다.** 51건 중 35건(69%)이 `none` 이다.
골든셋에서 colour 만 고정했을 때 5/5, action 을 함께 고정하자 2/5 가 됐던 것과
같은 모델, 같은 성질이다.

모든 응답의 reason 이 "too dark, blurred, or ambiguous" 계열이었다. 합성 장면이
실제 촬영보다 어둡기 때문으로 보이지만, **색은 그 상태에서도 맞혔다.**

### dusk 에서 드러난 것

조명을 1.0 → 0.6 → 0.35 → 0.15 로 끄는 동안,

- **규칙**은 어느 지점에서 `color=null` 로 **포기한다.** 어두우면 색조가
  노이즈이므로 믿지 않겠다는 설계다.
- **모델**은 끝까지 `green` 이라고 **답한다.** 거의 검은 화면에서도.

둘 다 "틀렸다" 고 말하기 어렵다. 다만 **포기할 줄 아는 쪽이 어느 쪽인지**는
분명하다. `scenarios/dusk.json` 이 이 대비를 기대값으로 고정하고 있다.

## 재생이 아무것도 검사하지 않던 문제

처음 붙였을 때 `--policy tape` 가 9/9 통과했다. **빈 기록으로도 9/9 였다.**

원인은 기대값이 `color` 와 `zone` 만 보고 있었기 때문이다. 둘 다 규칙 기반
특징에서 나오므로 모델이 무엇을 답하든 바뀌지 않는다. 게다가 모델이 69%
`none` 을 내므로 명령은 폴백이 만든다 — **폴백이 모델을 완전히 가린다.**
ADR-0009 에서 검증기가 4/5 를 거부하는 동안 폴백이 30fps 를 유지했던 것과
같은 일이, 이번에는 평가 쪽에서 일어났다.

고친 방법: 모델의 출력을 **따로** 적게 했다.

```json
"expect_tape": [
  { "at": 22, "vlm_colour": "green",
    "note": "규칙은 color=null 로 포기했는데 모델은 끝까지 green 이라고 한다" }
]
```

`expect` 와 `expect_tape` 를 섞지 않은 것이 요점이다. 섞으면 "모델을 검사하고
있다" 고 착각하게 된다. 지금은 빈 기록이 6개 기대를 떨어뜨리고, 같은 빈 기록이
규칙 기대 9개는 그대로 통과시킨다 — 두 사실 모두 시험으로 고정했다.

## 쓰는 법

```bash
./host/record_tape.py --every 1.5          # 강사가 실습 전에 한 번 (서버 필요)
./host/scenario_check.py --policy tape     # 수강생 — 서버도 GPU 도 없이
./host/sim_demo.py --scenario dusk --policy tape --tape-speed 1
```

`--tape-speed 1` 이면 기록된 지연(~2.8초)까지 재현한다. 34ms 제어 루프와
나란히 놓고 보면 비동기 구조가 왜 필요한지 설명이 필요 없다 (ADR-0008).

기록을 다시 뜨려면 서버를 띄운다 — `/health` 가 ok 라고 해도 요청 하나를 실제로
보내 보고 시작한다 (`docs/tech/notes/vlm-on-orin-nano.md`).
