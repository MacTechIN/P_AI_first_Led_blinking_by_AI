# ADR-0008 — VLM 은 제어 루프 밖에서 비동기로 돈다

상태: 채택   날짜: 2026-09-17   슬라이스: VS-3 (µ3.1)

## 배경
VS-3 은 판단을 규칙에서 VLM 으로 옮긴다. 옮기기 전에 그 비용을 실측했다
(`docs/tech/notes/vlm-on-orin-nano.md`).

| | 지연 |
|---|---|
| 제어 루프 한 스텝 (VS-2 실측) | 34.6 ms |
| 규칙 정책 판단 | 0.0 ms |
| **VLM 판단 (Qwen2.5-VL-7B Q4)** | **2200 ~ 2900 ms** |

약 70~85 배다.

## 결정
VLM 정책은 **제어 루프를 막지 않는다.** 별도로 돌며 최신 관측을 보고 의도를
갱신하고, 제어 루프는 마지막으로 받은 의도를 유지한 채 28 fps 로 계속 돈다.

## 근거
동기로 넣으면 루프가 0.4 fps 로 떨어진다. LED 는 몇 초에 한 번만 갱신되고,
사람이 물체를 움직여도 반응이 눈에 띄게 늦는다. 무엇보다 **점멸처럼 타이밍이
있는 동작은 호스트가 매 스텝 관여하지 않아야** 매끄럽다 — 이미 ADR-0001 이
정한 바이고, 이번 측정이 그것을 수치로 확증했다.

## 대안과 기각 사유
- **동기 호출**: 0.4 fps. 기각.
- **프레임 건너뛰기(N 프레임마다 VLM)**: 여전히 그 프레임에서 루프가 2.9 초 멈춘다.
  평균 처리율만 가리고 지터를 만든다. 기각.
- **더 작은 모델로 동기화**: 3B 도 1 초 안쪽이 되기 어렵고, 34.6 ms 예산에는
  어느 모델도 맞지 않는다. 문제의 성격이 모델 크기가 아니다. 기각.

## 결과
- `Policy` 인터페이스는 그대로 둔다. VLM 정책은 그 뒤에서 비동기로 동작하며,
  `decide()` 는 **가장 최근에 완성된 판단을 즉시 반환**한다 (블로킹하지 않는다).
- 관측이 판단보다 빠르므로 중간 프레임은 버려진다. 최신 프레임만 쓰면 된다 —
  ArgusSource 가 이미 `drop=true max-buffers=1` 로 그렇게 동작한다 (ADR-0006).
- 판단이 늦게 도착하므로 **결과에 관측 시각을 함께 남겨야** 재현이 가능하다.
- ADR-0007 의 이력(hysteresis)이 여기서도 필요하다. VLM 은 같은 장면에 대해
  조금씩 다른 답을 낼 수 있고, 그 차이를 전부 액추에이터로 흘리면 안 된다.
