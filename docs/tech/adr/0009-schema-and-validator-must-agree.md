# ADR-0009 — 스키마와 검증기는 같은 계약을 말해야 한다

상태: 채택   날짜: 2026-09-18   슬라이스: VS-3 (µ3.2, µ3.5)

## 배경
VLM 출력을 JSON 스키마로 강제하고(디코딩 단계), 그 뒤에 검증기를 한 번 더 두었다.
스키마는 `colour` 를 선택으로, 검증기는 `on`/`blink` 일 때 필수로 정의했다.

모델은 스키마를 따랐다 — `action: "blink"` 를 내면서 `colour` 를 생략했다.
검증기가 그것을 거부했다. **5회 중 4회가 실패했고**, 모델도 서버도 정상이었다.

## 결정
스키마가 허용하는 모든 출력을 검증기가 받아들여야 한다. `colour` 를 **항상 필수**로
바꾸고, `off`/`none` 에서는 값을 무시한다. 두 정의가 어긋나지 않도록
`test_schema_and_validator_agree` 로 고정한다.

## 근거
검증기는 잘못이 없었다 — 계약 위반을 잡는 것이 그 역할이다. 틀린 것은 **계약**이다.
두 곳에 계약을 적으면 갈라지고, 갈라지면 한쪽이 다른 쪽을 100% 거부하는 상태가
조용히 생긴다. 이 경우 제어 루프는 폴백 덕에 멀쩡히 돌았으므로 증상이 드러나지
않았다. 통계(`failed: 4`)를 보지 않았다면 놓쳤을 것이다.

## 대안과 기각 사유
- **검증기를 느슨하게**: 계약을 약화시킨다. 환각을 막는 유일한 관문이다. 기각.
- **조건부 required (JSON Schema `if/then`)**: llama.cpp 의 strict 모드가 지원하는지
  불확실하고, 지원해도 두 정의가 갈라질 여지는 남는다. 기각.
- **스키마만 믿고 검증기 제거**: 서버가 strict 를 지원하지 않을 수 있고, 검증기는
  모델 출력이 액추에이터에 닿는 유일한 통로다. 기각.

## 결과
- 모델은 `off`/`none` 에서도 의미 없는 `colour` 를 채워야 한다. 프롬프트에
  "무시되므로 아무 값이나 좋다" 를 명시했다.
- 계약을 두 곳에 적어야 한다면, **둘이 일치하는지 시험으로 고정**한다.
- 폴백이 증상을 가린다는 점을 기억해야 한다. VLM 통계(`requests/ok/failed/
  invalid/none`)를 항상 함께 본다.
