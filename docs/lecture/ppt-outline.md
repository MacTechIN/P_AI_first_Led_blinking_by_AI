# PPT 구성 교안 — Physical AI: 챗봇을 넘어 격전지로

`docs/labs/` 의 실습 자료와 `docs/tech/notes/` 의 실측 기록을 슬라이드로 옮긴 교안.

## 이 교안의 원칙

**모든 숫자는 실측값이다.** 업계 전망이나 추정치가 아니라 Jetson Orin Nano 한 대
위에서 직접 재서 나온 값만 쓴다. 출처를 슬라이드마다 각주로 단다.

그리고 **실패를 숨기지 않는다.** 잘 된 것만 보여주는 발표는 "우리도 해볼까" 다음에
오는 질문에 답하지 못한다. 막혔던 지점과 그때 무엇을 쟀는지가 이 교안의 설득력이다.

# 1부 — 패러다임 시프트 (25분)

> **이 부의 목표:** "챗봇과 뭐가 다른데?" 에 **구조적으로** 답한다.
> 감탄이 아니라 차이를 남긴다.

### S4 — 지난 3년: AI는 화면 안에 있었다
- 챗봇 · 코파일럿 · 문서 요약 — 전부 **텍스트 입출력**
- 공통점: **틀려도 되돌릴 수 있다.** 다시 생성하면 된다

### S5 — 화면 밖으로 나오는 순간 규칙이 바뀐다
- 비교표 (이 슬라이드가 1부의 핵심)

| | 챗봇형 AI | **Physical AI** |
|---|---|---|
| 출력 | 텍스트 | **물리적 상태 변화** |
| 틀렸을 때 | 재생성 | **되돌릴 수 없음** |
| 지연 허용 | 수 초 | **밀리초 (제어)** |
| 입력 | 사람이 입력 | **센서가 계속** |
| 실패 비용 | 어색한 문장 | **기구 파손 · 안전** |

- **말할 것:** "모터는 Ctrl+Z 가 없습니다."

### S6 — 왜 "격전지" 인가
- 세 가지 이유:
  1. **진입 장벽이 구조적이다** — 소프트웨어만으로 안 됨. 하드웨어 · 제어 · AI 가 동시에 필요
  2. **데이터가 현장에만 있다** — 공개 데이터셋으로 못 만든다
  3. **한 번 들어가면 교체가 어렵다** — 설비에 박히면 수년을 간다
- 📌 *말할 것: "그래서 늦게 들어가면 자리가 없습니다."*

### S7 — 그런데 왜 지금인가
- 세 가지가 동시에 가능해졌다:
  - **엣지 추론** — 8GB 보드에서 VLM 이 돈다 (오늘 시연한 것이 그것)
  - **비전·언어 통합** — 이미지를 보고 말로 답하는 모델
  - **온디바이스** — 인터넷 없이, 데이터를 밖으로 내보내지 않고
- 📎 `docs/tech/notes/vlm-on-orin-nano.md`

### S8 — 실측: 8GB 보드에서 무엇이 되나
- 표로 제시 (추정 아님, 실측)

| 항목 | 실측값 |
|---|---|
| 모델 | Qwen2.5-VL 3B (Q4) |
| 메모리 | 2.6 GB (여유 2.0 GB) |
| 색 판별 | **12색 전부 한 칸 이내** |
| 추론 지연 | 약 1~3초 |
| 인터넷 | **불필요** |

### S9 — 그런데 7B 는 죽었다
- **이 슬라이드가 1부에서 가장 중요하다.** 장밋빛만 보여주면 안 된다
- 7B: 적재 성공 → 카메라·제어 루프까지 견딤 → **추론 요청에서 사망**
- 스왑 3.7GB 전소
- **말할 것:** "적재되는 것과 운용되는 것은 다릅니다. 이걸 모르고 PoC 하면 데모는 되고 현장은 안 됩니다."
- 📎 `docs/tech/notes/vlm-on-orin-nano.md`

### S10 — Physical AI 가 실패하는 전형적 방식
- "성공 신호" 가 거짓인 사례 4종 (전부 이 프로젝트에서 실제로 겪음)

| 층위 | 성공처럼 보인 것 | 실제 |
|---|---|---|
| 하드웨어 | `/dev/video0` 존재 | 전 픽셀이 같은 값 |
| 모델 서버 | `model loaded`, health ok | 첫 요청에 사망 |
| AI 출력 | 스키마 통과 | 검증기가 80% 거부 |
| 운용 | 30fps 로 잘 돎 | **폴백이 실패를 가림** |

- **말할 것:** "네 번 다 화면상으로는 정상이었습니다."

### S11 — 그래서 이 분야의 핵심 역량은
- 기술 스택이 아니라 **판단**
  - "동작한다" 를 무엇으로 증명할 것인가
  - **측정하지 않은 것은 모른다**
- 📌 4부의 로드맵이 여기서 출발한다

### S12 — 1부 요약
- 화면 밖 = 되돌릴 수 없음
- 격전지인 이유 = 진입장벽 · 현장 데이터 · 락인
- 지금 가능한 이유 = 엣지에서 VLM 이 돈다
- **단, 되는 것과 운용되는 것은 다르다**

# 2부 — 아키텍처 해부 (45분)

> **이 부의 목표:** 참석자가 **뼈대 3개를 직접 그릴 수 있게** 한다.
> 도구 이름이 아니라 구조를 남긴다.

### S13 — 전체 구조 한 장
- 6계층 그림 (L0 하드웨어 ~ L5 관측)
- 📎 `docs/development_plan.md` 1절

### S14 — 뼈대 ①: 느린 판단과 빠른 제어를 분리한다
- **이것이 Physical AI 의 제1원칙**

### S15 — 왜 분리해야 하는가 (실측)
- 막대 비교:

```
제어 루프 한 스텝      34 ms
규칙 판단             0.0 ms
VLM 판단           3,306 ms   ← 97배
```

- 동기로 묶으면 **0.3 fps**
- 📎 `docs/tech/notes/vs2-latency-baseline.md`

### S16 — 분리하면 어떻게 되나
- 비동기 구조 그림: 작업 스레드 ↔ 제어 루프
- 실측: 판단 시간 **0.0 ms**, 루프 **30 fps** 유지
- **말할 것:** "모델은 3초 걸리는데 LED 는 끊기지 않습니다."

### S17 — 같은 원리가 세 층에서 반복된다
- 점멸 타이밍 → MCU (34ms 아래)
- VLM 판단 → 비동기 (3초 위)
- 출력 흔들림 → 이력
- **말할 것:** "이건 하나의 원리가 세 번 나타난 겁니다."

### S18 — 실례: 타이밍을 호스트가 쥐면
- 호스트 주도 점멸 vs MCU 주도 점멸 (시연 가능)
- USB 지연 + 스케줄러 지터 → 100ms 주기에서 눈에 띄게 떨림
- 📎 `docs/labs/02-actuator-timing.md`

### S19 — 뼈대 ②: 모델 출력은 검증을 통과해야 한다
- 3중 관문 그림

### S20 — 세 관문이 중복이 아닌 이유
| 관문 | 막는 것 | 우회 가능? |
|---|---|---|
| 스키마 강제 | 구조 오류 | 서버가 미지원일 수 있음 |
| 계약 검증 | 없는 장치·범위 밖 | 호스트 우회 가능 |
| **펌웨어 한계** | 물리적 위반 | **우회 경로 없음** |
- **말할 것:** "선언은 안내문이고 펌웨어는 잠긴 문입니다."

### S21 — 실패 사례: 계약이 갈라졌을 때
- 스키마는 `colour` 선택 / 검증기는 필수 → **5회 중 4회 거부**
- **아무것도 고장나 보이지 않았다** (폴백이 30fps 유지)
- 📎 ADR-0009

### S22 — 그래서 "모르겠다" 를 합법으로 만든다
- `none` 을 스키마에 넣지 않으면 모델은 **반드시 지어낸다**
- 실제 응답: *"too dark, blurred or ambiguous"*
- `none` ≠ `off` — **판단 불가와 끄라는 지시는 다르다**

### S23 — 뼈대 ③: 역량을 데이터로 선언한다
- 선언 하나 → **스키마 · 검증기 · 전송 문자열** 셋이 파생

### S24 — 증명: 코드 0줄로 장치 추가
- 실측:
```
추가 전  파이썬 md5 51a8999…  스키마 3옵션 / 1장치
servo_pointer.json 추가 (파이썬 수정 없음)
추가 후  파이썬 md5 51a8999…  스키마 5옵션 / 2장치
```
- 📎 ADR-0010

### S25 — 계약이 막는 것들 (시연)
- `laser.fire` → 없는 장치
- `angle=999` → 범위 초과
- 환각이 **하드웨어에 닿지 않는다**

### S26 — 뼈대를 다 합치면
- 전체 아키텍처 한 장 (S13 재등장, 이번엔 뼈대 3개 강조)

### S27 — AI 를 쓸 문제 / 쓰지 말 문제
- **2부에서 가장 실무적인 슬라이드**

| 과제 | 규칙 | VLM | 승자 |
|---|---|---|---|
| 색 판별 | 보통 | **좋음** | VLM |
| **위치 판단** | **9/9, 7ms** | 3/9, 2.5초 | **규칙 (330배 빠름)** |
| "정리되어 있나" | **불가능** | 가능 | VLM |

- 📎 `docs/tech/notes/direction-rule-vs-vlm.md`

### S28 — 위치 실패의 진짜 모습
- VLM 이 9개 전부 `left` 로 답함 → 맞은 3개는 우연
- **말할 것:** "3/9 만 보면 '좀 부정확' 으로 읽힙니다. 답변을 보면 **아예 안 보고 있습니다.**"
- **교훈:** 정확도 숫자 하나로 모델을 판단하지 마라
- **원칙:** 색은 의미 해석, 위치는 산술. **산술을 모델에게 시키지 마라**

- 목표 화면: 색지를 들면 LED 가 같은 색
- 📎 `docs/labs/` 전체

### S30 — 준비물과 배선
- 부품표 + 배선도
- 📎 `docs/labs/00-setup.md`

### S31 — ⚠️ 부품 함정 4가지 (실제로 겪은 것)
- **이 슬라이드가 핸즈온 시간을 절반으로 줄인다**

| 함정 | 증상 |
|---|---|
| Camera Module 3 (IMX708) | JetPack 미지원. **`/dev/video0` 은 생김** |
| 15핀 케이블 | 꽂히는데 접점이 안 닿음 (Orin 은 22핀) |

| 공통 저항 1개 | 노랑이 **빨강**으로 나옴 |

### S32 — 질문: 무지개 색은 어떻게 표현하지?
- **이 질문이 3부의 축이다**
- 참석자에게 먼저 물어본다 (RGB? 색 이름? 번호?)

### S33 — 색상환 — 색은 1차원이다
- hue 원형 그림
- 색을 **각도 하나**로 표현 → 모델이 다룰 어휘가 단순해진다
- ⚠️ **OpenCV 는 0–179** (360 이 아니다)

### S34 — 빨강은 두 번 나온다
- hue 0 근처와 179 근처로 **갈라짐**
- 평균 내면 (2+175)/2 = 88.5 → **정확히 청록**
- **그래서 최빈값을 쓴다**
- 📌 *청중 질문 유도: "평균이 왜 안 되죠?"*

### S35 — 색조 하나가 명령이 되기까지
- 인터랙티브 시연 (슬라이더)
```
"green" → hue 60 → RGB(0,255,0) → "RGB 0 255 0 / LEVEL 90 / ON"
```
- 📎 `docs/visuals/vlm-colour-loop.html`

### S36 — 무지개 돌리기 (시연)
- `./host/rainbow.py --period 8`
- **말할 것:** "이건 AI 가 아닙니다. 색상환을 한 바퀴 도는 것뿐입니다."
- 📌 *다음 슬라이드에서 AI 를 넣는다 — 대비가 핵심*

### S37 — 왜 이건 호스트가 타이밍을 쥐나
- 뼈대 ① 의 **예외**
- 펌웨어는 색 순환을 모름 + 페이드는 밀리초 정밀도 불필요
- **말할 것:** "원칙에는 예외가 있고, 예외를 설명할 수 있어야 원칙을 이해한 겁니다."

### S38 — 이제 AI 를 넣는다
- 로컬 VLM 기동 → 카메라가 본 색을 LED 가 재현
- 시연: 색지를 바꿔 든다

### S39 — 서버 띄울 때 걸리는 함정
| 플래그 | 없으면 |
|---|---|
| `--parallel 1` | 슬롯 4개 → **첫 요청에 사망** |
| 이미지 768×432 | 1280×720 은 batch 초과로 abort |
| `-c 4096` | **줄이면 오히려 깨짐** |
| GUI 끄기 | 가용 2.3GB → 6.4GB |
- **말할 것:** "`/health` 가 ok 라고 동작하는 게 아닙니다."

### S40 — 측정: VLM 은 색을 얼마나 맞히나
- 12색 1바퀴 결과표 (색 견본 포함)
- **정확히 일치 6/12, 나머지 6개도 색상환 한 칸 이내**
- 한 칸을 넘어 틀린 적 **없음**
- 📎 `docs/visuals/vlm-colour-loop.html`

### S41 — "100% 정확" 이라고 쓰지 않은 이유
- 관용 채점하면 12/12
- **그러나 그건 틀린 교훈을 준다**
- 경계의 이름은 사람도 갈린다 → **"한 칸 안에서 정확"** 이 정직한 표현
- **말할 것:** "지표를 유리하게 고르면 자기 자신을 속입니다."

### S42 — 자동노출이 측정을 망치는 두 방향
- **이 슬라이드는 실습의 숨은 핵심**

| 상황 | AE 효과 | 결과 |
|---|---|---|
| LED 를 전역 밝기로 재면 | **상쇄** (+0.02) | 있는데 **안 보임** |
| 움직임을 차분으로 재면 | **증폭** (3.2배) | 없는데 **보임** |

- 📎 `led-camera-detection.md`, `motion-threshold.md`

### S43 — 임계값은 추측하지 않는다
- 노이즈 바닥 먼저 측정 → 그 위에서 임계값 선정
```
정지 노이즈 p95  0.300
신호 평균        3.245   (여유 10.8배)
임계 0.601 → 오경보 0%, 검출 100%
```

### S44 — 출력이 떨린다 (그리고 고치는 법)
```
원본      20스텝 중 18회 전송
양자화    11회      ← 부족
이력       2회      ← 해결
```
- 양자화만으로 안 되는 이유: **경계 위에서 진동**
- **원칙:** 판단의 분해능을 **관측의 신뢰도**에 맞춘다

### S45 — 3부 요약
- 색은 **각도 하나**로 표현된다 (빨강은 두 번 나온다)
- AI 는 색을 **한 칸 이내**로 맞힌다
- 측정 방법이 결론을 만든다 (AE 가 두 방향으로 망친다)
- 지표를 유리하게 고르지 마라

# 4부 — 실전 적용하기 (35분)

> **이 부의 목표:** 참석자가 **다음 주 월요일에 할 한 가지**를 정해서 나간다.

### S46 — Physical AI 가 왜 필요한가 (조직 관점)
- 세 가지 동인:
  1. **사람이 보던 것을 기계가 본다** — 검사 · 감시 · 계수
  2. **데이터가 밖으로 안 나간다** — 온디바이스 = 보안 · 규제 대응
  3. **네트워크 없이 돈다** — 공장 · 현장 · 오지

### S47 — 그런데 "AI 를 넣자" 로 시작하면 실패한다
- 흔한 실패 순서:
  ```
  AI 도입 결정 → PoC → 데모 성공 → 현장 투입 → 실패
  ```
- 실패 지점: **데모 환경과 운용 환경의 차이** (S9 의 7B 사례)

### S48 — AX 전략가의 로드맵 — 4단계
- **4부의 핵심 슬라이드**

| 단계 | 질문 | 산출물 | 기간 |
|---|---|---|---|
| **0. 측정** | 지금 사람이 무엇을 보고 있나 | 관측 목록 + 빈도 | 2주 |
| **1. 규칙** | 규칙으로 되는 것은? | 규칙 기반 베이스라인 | 4주 |
| **2. AI** | 규칙으로 안 되는 것만 | AI 판단 + **A/B 비교** | 8주 |
| **3. 운용** | 나빠진 걸 어떻게 아나 | 골든셋 + 안전장치 | 지속 |

- **말할 것:** "1단계를 건너뛰면 2단계에서 무엇이 좋아졌는지 모릅니다."

### S49 — 단계 0 이 가장 중요한 이유
- "AI 로 무엇을 할까" 가 아니라 **"지금 사람이 무엇을 보고 있나"**
- 사람이 보고 있지 않은 것은 AI 도 볼 필요가 없다
- 📌 워크시트 배포: *우리 현장에서 사람이 눈으로 보는 것 5가지*

### S50 — 단계 1 을 건너뛰지 마라
- 규칙 베이스라인이 주는 것:
  - **비교 기준** (AI 가 얼마나 나아졌나)
  - **폴백** (AI 가 죽었을 때)
  - **원인 분리** (모델 문제 vs 배선 문제)
- 실측: 위치 판단은 **규칙이 330배 빠르고 정확**했다

### S51 — 무엇부터 준비해야 할까
| 영역 | 준비할 것 | 흔한 착각 |
|---|---|---|
| 사람 | **측정할 줄 아는 사람** | "AI 전문가부터" |
| 데이터 | 현장 이미지 + **기대 출력** | "데이터만 많으면" |
| 하드웨어 | 실제 운용 조건의 보드 | "일단 좋은 GPU" |
| 프로세스 | **골든셋 · 회귀 탐지** | "잘 되면 끝" |

### S52 — 안전은 나중이 아니다
- **모터를 붙이기 전에** 워치독을 만든다
- 붙이고 나서 만들면 **그 사이 실수 한 번이 기구를 부순다**
- 안전 상태는 장치마다 다르고 **자명하지 않다** (서보의 "중립 복귀" 가 더 위험할 수 있음)

### S53 — 다음 주 월요일에 할 한 가지
- 참석자가 **하나만** 고른다:
  - [ ] 우리 현장에서 사람이 눈으로 보는 것 5가지 적기
  - [ ] 그중 **규칙으로 되는 것** 표시하기
  - [ ] 보드 하나 주문해서 **운용 조건으로** 재보기
- 📌 *워크시트 배포 + 5분 작성 시간*
